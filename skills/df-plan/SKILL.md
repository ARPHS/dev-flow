# Plan

先读取项目规则、相关代码、已有 issue 或规格和可用验证命令。把用户目标整理为问题理解、范围、成功标准、约束、关键边界、方案取舍、任务依赖和验证方式。

只询问会改变产品结果、兼容性、数据安全或外部操作的未知信息。能从仓库和现有约定确定的内容自行确认。给出推荐方案和替代方案的实际影响，不为不存在的未来需求设计扩展。

计划应让另一个 agent 可以执行，包含行为切片、涉及的模块或接口、每步完成定义和验证方式。避免把每个函数或每条命令都写成计划项。用户要求执行或明确批准后，可以衔接 `df-flow`，不重复索取同一批准。

方案发生实质变化时保留原决定和变更原因，重新分析受影响任务与验证覆盖。只讨论时不要写代码或创建无关台账。
