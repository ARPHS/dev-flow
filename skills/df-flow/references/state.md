# 持久化与恢复

## 何时创建

只有 `feature`、`project`、需要跨会话恢复或用户明确要求时，在目标项目创建 `.flow/`：

```text
.flow/
├── project.md    # 项目画像：命令和约定（可跨任务复用）
├── task.md       # 目标、验收条件、切片和验证计划
├── progress.md   # 当前断点、验证证据和下一步（机器可检查）
└── decisions.md  # 只有存在产品或架构取舍时创建
```

## 不进入版本库

首次创建 `.flow/` 时检查它是否已被忽略（`git check-ignore -q .flow`）。未被忽略时，把 `.flow/` 追加到 `.git/info/exclude`（本地生效、不修改项目文件），并在报告中告知用户。用户希望共享台账时才改为提交。

## 模板

### project.md

```markdown
# 项目画像
- 语言/框架：
- test：`<命令>`（来源：CI / package.json / 推断）
- lint/typecheck：`<命令>`
- build：`<命令>`
- run：`<命令>`
- 约定：<分支、提交信息、目录结构等>
- 已知基线失败：<测试名或"无">（记录于 <日期>）
```

### task.md

```markdown
# <任务名>
- 级别：feature | project
- 目标：
- 范围外：
## 验收条件
- [ ] AC1：<可观察行为>
## 切片
1. [ ] <切片> —— 验证：<命令/操作>
## 验证计划
```

### progress.md

前两行字段名固定，`df-verify/scripts/check_evidence.py` 会读取它们：

```markdown
状态：in-progress | blocked | done
证据版本：<fingerprint.py 的输出>

## 当前
- 切片：
- 分支/工作区：
- 未提交文件：<git status --short 摘要>
## 验证证据
| 命令 | 目录 | 退出码 | 结果 |
|---|---|---|---|
## 阻碍
## 下一步
```

### decisions.md

```markdown
## <日期> <决定>
- 备选：
- 依据：
- 影响：
```

## 更新时机

- 每个切片验证通过后。
- 被阻塞、向用户提问、上下文接近上限、结束会话前。
- 标记 `状态：done` 前必须先运行 `df-verify`，并把 `证据版本` 更新为当前指纹。

## 恢复

先读 `.flow/`，再检查文件、分支、提交、未跟踪文件，并重新运行最近一次的验证命令。记录与现场冲突时以现场为准并修正记录。`证据版本` 与当前指纹不一致时，记录中的验证结果视为过期。不要为了让状态看起来完整而丢弃未提交改动。

任务完成后可以保留 `.flow/` 供后续恢复，也可按项目约定归档。不要删除用户可能仍需的记录。
