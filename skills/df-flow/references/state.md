# 持久化与恢复

只有 `feature`、`project` 或用户明确要求时，在目标项目创建 `.flow/`。建议使用以下最小文件：

```text
.flow/
├── task.md       # 目标、验收条件、任务和状态
├── progress.md   # 当前断点、验证证据和下一步
└── decisions.md  # 只有存在产品或架构取舍时创建
```

`task.md` 至少包含目标、范围、验收条件、任务依赖和验证计划。`progress.md` 至少包含阶段、当前任务、工作区、未提交文件、最近命令及退出码、已完成证据、阻碍和下一步。`decisions.md` 记录决定、备选方案、依据、影响和日期。

保存状态前先检查工作区和 Git 实际状态。恢复时先读状态，再检查文件、分支、提交、未跟踪文件和测试结果。若记录与现场冲突，以现场证据为准并修正状态。不要为了让状态看起来完整而丢弃未提交改动。

任务完成后，用户没有要求保留历史时可以将 `.flow/` 留在项目中供后续恢复，也可以按项目约定归档。不要删除用户可能仍需的记录。
