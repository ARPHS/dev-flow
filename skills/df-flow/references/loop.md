# 实现循环

## 进入任务

读取项目规则和同类实现，确认工作目录、分支、已有改动和可用命令。保留用户已有修改，不把无关文件加入任务。若需要隔离，先创建符合项目约定的 worktree；不需要隔离时直接使用合适的工作区。

## 行为切片

每个切片都应能由用户路径、公共接口、命令、测试或测量观察到。切片顺序优先选择能验证架构假设的最小路径，再补边界和错误路径。不要先写一批无法单独验证的基础层代码。

行为变化通常采用红、绿、重构：先写能因预期原因失败的测试，确认失败，再写最小实现，运行通过后整理设计。文档、配置、样式或测试工具等改动采用实际适用的检查，不制造只匹配实现文本的测试。

## 失败处理

命令失败时保留完整命令、工作目录、退出码和关键输出。先区分代码失败、测试失败、环境失败和基线失败。重复失败时缩小复现范围并改变观测手段。连续三轮仍无新证据时停止当前分支，记录阻碍和需要的决定，不伪造进展。

## 收尾

检查完整 diff 和未跟踪文件，确认范围、错误处理、兼容性和验收条件。运行适用的最终验证，复查结果对应当前代码而非旧提交。用户明确授权提交、合并或推送时，先重新核对基线和工作区，再执行对应动作。
