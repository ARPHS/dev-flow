# 任务分流

## 不进入主流程

以下请求直接完成或直接回答：只改文案、单点重命名、局部格式修复、只读查询、解释代码、只要求审查、只要求设计，以及能够在一次检查中确认的低风险小改动。仍需遵守项目规则并在声称完成前做适用验证。

## 进入 feature

满足任一条件即可进入 `feature`：跨越多个模块、改变用户可观察行为、涉及权限或错误处理、需要新增或修订测试、存在多个验证步骤、需要在后续会话继续，或用户明确要求持续开发。

先写验收条件和任务顺序，再边实现边验证。不要为了流程形式创建 PRD 或长计划。

## 进入 project

满足任一条件即可进入 `project`：新项目、公共 API 或数据格式变化、迁移、认证授权、安全边界、并发一致性、性能目标、架构重组、无法逆转的操作，或多个可行方案会导致不同产品结果。

先给出问题理解、约束、方案取舍、验收条件、验证方法和风险。实现授权后可以连续推进。产品选择、破坏性兼容变化和外部不可逆操作仍需用户决定。

## 升级和降级

实现中发现数据、兼容性、性能或安全影响高于预期时升级级别，并记录原因。证据表明任务比预期简单时可以降级，不保留无用台账。级别只描述工作量，不改变用户授权边界。
