# Review

先固定审查对象和基线。代码审查包含未跟踪文件和完整 diff，不能只看最后一个文件或最后一次提交。方案审查对照项目现状、成功标准、依赖和更简单的选择。

从两个维度检查：

- 需求：行为是否满足验收条件，正常路径、边界、错误、权限和兼容性是否覆盖。
- 工程：设计是否清晰，是否引入回归、重复逻辑、范围蔓延、无效测试或无法维护的绕过。

每个问题给出位置、原因、影响、复现或验证依据，并分为 Critical、Important、Minor。Critical 和 Important 在用户要求的范围内修复并复验。没有问题时直接说明未发现阻塞项，不凑问题。

审查结论只对固定的代码、提交和文档版本有效。任何实质修改、同步主分支或变更方案后重新检查受影响范围。未经用户授权，独立审查不自动合并、推送或发布。
