# Verify

根据改动的行为和风险选择最小但充分的验证集合。先运行最接近改动的检查，再运行项目要求的整体检查。适用时包括测试、类型检查、lint、构建、CLI/API 调用、浏览器操作、旧数据演练和性能测量。

每项证据记录命令、工作目录、退出码和关键输出。说明哪些检查未运行以及原因。区分本次失败、已知基线失败和环境阻碍。不要用静态阅读、代码存在、代理报告或未执行的命令替代运行结果。

验证行为而不是实现文字。检查成功路径、边界、错误、权限、重试、兼容性和用户实际入口。UI 或性能改动需要真实操作或测量，不能只依赖单元测试。发现问题时返回 `df-flow` 或 `df-debug`，修复后重新运行受影响检查。
