# Debug

```text
失败样例 → 最小复现 → 假设 → 观测 → 修复 → 回归验证
```

1. **失败样例**：保存真实失败输入、环境、命令、退出码和完整输出。拿不到失败现场时先设法复现，不凭描述直接改代码。
2. **最小复现**：把问题缩小为一条可重复运行的命令或测试，区分代码、数据、环境和基线因素。能写成失败测试时优先写成测试。
3. **假设和观测**：每个假设配一个能证伪它的观测（日志、断点、二分、对照输入）。一次只验证一个假设，不在没有证据时连续猜测。
4. **修复根因**：修复导致问题的原因，而不是症状所在的位置。说明为什么这样修能覆盖同类输入。
5. **回归验证**：加入不只匹配当前实现的回归测试或等价检查，确认它在修复前失败、修复后通过，并运行相关测试集。性能问题记录相同条件下的前后指标。

## 禁止

不通过放宽断言、删除或跳过测试、吞掉错误、增加重试或 sleep 掩盖时序问题、绕过真实入口来让结果变绿。

## 记录

每轮在回复（或 `.dev-flow/progress.md`）中保持：

```text
现象：<失败命令 → 输出摘要>
复现：<最小命令>
假设 1：<…> —— 观测：<…> —— 结果：证实 / 否定
根因：<…>
修复：<文件 → 改动>
回归：<测试名> 修复前失败 / 修复后通过
```

连续三轮没有新证据时停止，保留现场并报告已排除的假设、当前最可能的方向和需要的信息或权限。
