# Plan

先读取项目规则、相关代码、已有 issue 或规格和可用验证命令。能从仓库和现有约定确定的内容自行确认。

## 提问

只询问会改变产品结果、兼容性、数据安全或外部操作的未知信息。一次集中提出，每个问题附上你的推荐答案和理由，便于用户直接确认。不为不存在的未来需求设计扩展。

## 输出

```markdown
# <计划名>
## 问题理解
## 范围
- 包含：
- 不包含：
## 验收条件
- AC1：<可观察的行为>
## 方案
- 推荐：<方案> —— 理由
- 备选：<方案> —— 放弃原因 / 适用场景
## 切片
| # | 行为切片 | 涉及模块/接口 | 完成定义 | 验证方式 | 依赖 |
## 风险和待决事项
## 验证计划
<项目命令 + 每条 AC 的验证方式>
```

计划应让另一个 agent 可以执行。切片以可观察行为划分，不把每个函数或每条命令写成计划项。

## 衔接

- 只讨论时不写代码，也不创建台账。
- 用户要求执行或明确批准后衔接 `df-flow`，计划即视为 `project` 级别的已确认设计，不重复索取同一批准；需要跨会话时把计划写入 `.dev-flow/task.md`。
- 方案发生实质变化时，在 `.dev-flow/decisions.md` 或回复中保留原决定和变更原因，重新分析受影响的切片与验证覆盖。
