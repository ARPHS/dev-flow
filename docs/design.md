# 设计说明

## 问题

强制所有任务进入完整流程会浪费上下文和用户时间，完全手动又容易让新功能缺少验证和收尾。`dev-flow` 把触发方式和流程重量分开处理：明确的开发意图可以连续推进，工作量由风险和验证难度决定。

## 原则

1. 先理解真实入口和项目约定，再决定工作量。
2. 用户授权实现后默认持续推进，只在产品、兼容性、数据、依赖和外部副作用边界暂停；`project` 级别在设计后停顿一次，用户已确认方案或明确要求直接做时除外。
3. 先取得可观察反馈，再扩大实现范围。
4. 运行证据优先于代码阅读和代理报告，证据绑定代码版本。
5. 重复纠正优先固化为 API、类型、静态检查、测试或运行时约束。
6. 状态持久化只服务于恢复和协作，不为小任务制造文件。
7. 协作按收益启用，主控负责核对集成结果；高风险任务的审查与实现分离。

## 技能写法

- 正文只放硬规则、步骤和**必填输出模板**。模型对固定格式的遵循度远高于对长句清单的遵循度，模板同时让用户能够一眼发现偏差。
- 细节、示例和判定表放入 `references/`。
- 流程和判断写在技能里。只有文字做不到的事（由程序执行命令并记录退出码、给工作区拍快照）才交给一个配套 CLI：`plugins/dev-flow/skills/df-verify/scripts/evidence.py`，只用标准库和 git，不引入第二个脚本入口。

## 软约束与硬约束

技能文本是软约束，模型可能跳过。插件用**程序记录的证据**补充：`evidence.py run` 执行验证命令，把退出码、输出摘要和工作区快照写入 `.dev-flow/evidence.jsonl`；`evidence.py report` 生成证据表，并列出每条记录之后改动过的文件。最终报告的证据表由它生成，而不是由模型手写。

工具只报告事实，不判断有效性："某个文件变了是否影响这项检查"是判断题，由 df-verify 的规则决定，并在报告中写明理由，便于用户和审查者复核。早期版本用整个工作区的哈希做是非判断，会把测试写出的数据文件、缓存等误判为代码变化，而且排除列表永远列不全，因此放弃。

快照的实现选择：

- **用 git tree 而不是自定义哈希**：内容寻址、自动遵守忽略规则，变化列表直接来自 `git diff --name-status`；提交本身不改变内容，也就不会使证据失效。
- **临时暂存区**：复制项目暂存区后在副本上 `git add`，不碰用户的暂存区。复制时保留文件修改时间，否则会绕过 git 对"同一秒内、大小不变的修改"的检测（racy-git），得到旧内容。
- **独立对象目录**：通过 `GIT_OBJECT_DIRECTORY` 把新对象写入 `.dev-flow/objects/`，再通过 `GIT_ALTERNATE_OBJECT_DIRECTORIES` 复用项目已有对象。项目的 `.git` 不增长，清理就是删除一个目录。
- **大文件和容量上限**：超过 10MB 的未跟踪文件不纳入快照并在报告中提示；`objects/` 超过 200MB 时自动清空。快照 id 的比较不依赖对象，跨任务复用基线在对象被清理后仍然可用。

不提供 Stop hook：它只能拦截一次，本质上只是提醒，却要用户手填随版本变化的插件路径，路径失效时还会导致每次结束都被拦截。

## 评测

技能改动的效果只能通过行为评测确认。`evals/` 使用真实夹具、无界面 agent 运行和程序化评分，并支持 `--no-plugin` 对照组。`tests/test_evals.py` 保证每个评分器能区分未修改的夹具和参考答案。

## 对 Lauren Tan 实践的吸收

代码库、架构、类型、lint 和测试承担低成本的确定性约束。运行时验证提供产品行为和性能证据。技能和规则只处理不能直接编码的判断。人工审查关注剩余的不确定性。功能地图和项目专用验证 CLI 是在真实使用中逐步建设的能力，不作为每个仓库安装后的强制依赖。

## 不做的事

插件不自动安装任何 hook，不修改使用者项目的 `.claude/`、`CLAUDE.md`、`.gitignore` 或 `.codex/config.toml`，不自动提交、推送、发布或合并。

## 已知限制

- `agents/` 只在 Claude Code 中注册为子代理。Codex 中由主控用 `spawn_agent`（`fork_turns: "none"`）按同一份角色正文派发，审查独立，但工具限制只靠文字约束，由主控事后用 `git status` 核对。
- Codex 默认沙箱只允许写工作区，不允许写 `.git/`：因此 `.dev-flow/` 用自带的 `.gitignore` 而不是 `.git/info/exclude` 来忽略，`evidence.py` 的所有写入都在 `.dev-flow/` 内；并行 worktree 和提交需要用户批准提权。
- 评测运行器目前只支持 Claude Code CLI。
